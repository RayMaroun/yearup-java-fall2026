Payroll Calculator, Refactored

Your payroll calculator, reorganized into methods, with exactly the same output.

What you are building

The same payroll program, in a new project: same three questions, same output, but the code is reorganized into smaller methods. The output does not change at all, and that is how you know the refactor is correct.

No new feature. The lesson is planning the split before you touch the code, and passing values into methods and getting values back out.

Where people get stuck

  • The value dies inside the method. A method that calculates must hand the number back with return, or main never sees it.
  • The result goes nowhere. main calls the method but does not keep what comes back. Store the result in a variable.
  • A Scanner in every method. Read the input in main and pass the values (or the Scanner) as parameters. See the One Scanner page.
  • The output changed. The output is the test. If it differs from step 1, undo the last move and try again.

The one idea

Refactoring changes the shape of the code, never its behavior. Plan the pieces on paper, move one at a time, and run after each move.
