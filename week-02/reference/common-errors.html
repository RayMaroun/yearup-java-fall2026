Common Errors

The messages you will meet this week, word for word. Read the first line of the message: it usually names the fix.

Show
Compile

Reaching a private field from outside

See it
java: name has private access in Person

The field is private, so only code inside Person can touch it. Main cannot.

FixGo through the getter to read it and the setter to change it.

Before
System.out.println(instructor.name);
After
System.out.println(instructor.getName());
Compile

Calling a getter that was never written

See it
java: cannot find symbol
  symbol:   method getAge()
  location: variable learner of type Person

The class has an age field but no getAge() method, so there is nothing to call.

FixAdd the getter to the class (Generate > Getter), or check the spelling of the name.

Before
public class Person {
    private int age;
    // no getAge()
}
After
public class Person {
    private int age;
    public int getAge() {
        return this.age;
    }
}
Compile

No constructor matches the new

See it
java: constructor Person in class Person cannot be applied to given types;
  required: String,int
  found:    no arguments
  reason: actual and formal argument lists differ in length

The only constructor needs a name and an age. Once you write any constructor, Java no longer gives you an empty one.

FixPass what required lists, or add a no-argument constructor to the class.

Before
Person guest = new Person();
After
Person guest = new Person("Guest", 0);
Compile

No overload matches the call

See it
java: no suitable method found for greet(no arguments)
    method Person.greet(String) is not applicable
      (actual and formal argument lists differ in length)
    method Person.greet(String,int) is not applicable
      (actual and formal argument lists differ in length)

There are two greet methods and the call fits neither. The compiler lists every overload it tried.

FixMatch one parameter list: types, count and order. Swapped order, like greet(3, "Brandon"), shows as incompatible types instead.

Before
instructor.greet();
After
instructor.greet("Brandon");
instructor.greet("Brandon", 3);
Compile

Running total with no starting value

See it
java: variable total might not have been initialized

total += week reads total first, and a local variable has no value until you give it one.

FixStart the total at 0, before the loop.

Before
int total;
for (int week = 1; week <= 10; week++) {
    total += week;
}
After
int total = 0;
for (int week = 1; week <= 10; week++) {
    total += week;
}
Compile

Forgetting new

See it
java: cannot find symbol
  symbol:   method Person(String,int)
  location: class Main

Without new, Java reads Person(...) as a call to a method named Person, and there is none.

FixPut new in front of the constructor call.

Before
Person learner = Person("Natalie", 37);
After
Person learner = new Person("Natalie", 37);
Compile

Return only inside the loop

See it
java: missing return statement

The method promises an int. If the loop ends without a match, nothing is returned, and the compiler refuses that path.

FixReturn something after the loop too, like -1 for "not found".

Before
public static int findCity(String[] cities, String target) {
    for (int i = 0; i < cities.length; i++) {
        if (cities[i].equals(target)) {
            return i;
        }
    }
}
After
public static int findCity(String[] cities, String target) {
    for (int i = 0; i < cities.length; i++) {
        if (cities[i].equals(target)) {
            return i;
        }
    }
    return -1;
}
Compile

Using a StringBuilder as a String

See it
java: incompatible types: StringBuilder cannot be converted to String

A StringBuilder is its own type, not a String, even though it holds text.

FixCall toString() when the text is finished.

Before
String toolList = tools;
After
String toolList = tools.toString();
Runtime

Text that is not a number

See it
Exception in thread "main" java.lang.NumberFormatException: For input string: " 12"
	at java.base/java.lang.NumberFormatException.forInputString(NumberFormatException.java:67)
	...
	at com.pluralsight.Main.main(Main.java:11)

parseInt accepts digits only. A space, a letter or a decimal point ("twelve", "12.5") makes it throw.

FixTrim the input first; use Double.parseDouble for decimals.

Before
int boxes = Integer.parseInt(boxesInput);
After
int boxes = Integer.parseInt(boxesInput.trim());
Runtime

Date in the wrong format

See it
Exception in thread "main" java.time.format.DateTimeParseException: Text '10/17/2002' could not be parsed at index 0
	at java.base/java.time.format.DateTimeFormatter.parseResolved0(DateTimeFormatter.java:2052)
	...
	at com.pluralsight.Main.main(Main.java:13)

LocalDate.parse(text) reads only yyyy-MM-dd. The index says where the text stopped matching.

FixPass a formatter whose pattern matches what the user types.

Before
LocalDate birthday = LocalDate.parse(birthdayInput);
After
DateTimeFormatter inputFormat =
    DateTimeFormatter.ofPattern("MM/dd/yyyy");
LocalDate birthday =
    LocalDate.parse(birthdayInput, inputFormat);
Runtime

Position past the end of a String

See it
Exception in thread "main" java.lang.StringIndexOutOfBoundsException: String index out of range: 20
	at java.base/java.lang.StringLatin1.charAt(StringLatin1.java:48)
	...
	at com.pluralsight.Main.main(Main.java:15)

The String has 14 characters, at positions 0 to 13. With substring the message reads begin 0, end 20, length 10.

FixKeep positions below length(); get them from indexOf instead of counting by hand.

Before
String trackingCode = "USA-12981-Y-22";
char hasShipped = trackingCode.charAt(20);
After
String trackingCode = "USA-12981-Y-22";
char hasShipped = trackingCode.charAt(10);
Runtime

One slot too far in an array

See it
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 7 out of bounds for length 7
	at com.pluralsight.Main.main(Main.java:9)

Seven slots means indexes 0 to 6. With <= the loop asks for slot 7 on its last pass.

FixLoop while i < length, or use a for-each loop.

Before
for (int i = 0; i <= listOfNumbers.length; i++) {
After
for (int i = 0; i < listOfNumbers.length; i++) {
Runtime

A field that was never set

See it
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.toUpperCase()" because the return value of "com.pluralsight.Person.getName()" is null
	at com.pluralsight.Main.main(Main.java:23)

The empty constructor never gave name a value, so it is still null, and you cannot call a method on nothing.

FixGive every field a value in every constructor, or call the setter before you use it.

Before
public Person() {
}
After
public Person() {
    this("Guest", 0);
}
Runtime

== on Strings

See it

No error. Console:

Different text

builtLanguage was made at run time, so it is a different object from "Java". == compares objects, not text.

FixCompare text with .equals() or .equalsIgnoreCase().

Before
if (language == builtLanguage) {
After
if (language.equals(builtLanguage)) {
Runtime

A loop that never ends

See it

No error. Console, forever:

Week 1
Week 1
Week 1
...

Nothing in the body changes week, so week <= 4 stays true.

FixStop the program with the red square, then add the update that moves toward the end.

Before
int week = 1;
while (week <= 4) {
    System.out.println("Week " + week);
}
After
int week = 1;
while (week <= 4) {
    System.out.println("Week " + week);
    week++;
}
IntelliJ

The wrong main runs

No error. The Run window shows another program's output.

Run configuration (top right): Main

With two classes that have a main, the Play button runs the last run configuration, not the file you are looking at.

FixClick the green arrow next to the main you want once, or pick it in the run configuration list.

Before
Play button: runs Main
After
Configuration list: PersonApp, then Play
IntelliJ

The debugger never stops

See it

No error. The program runs to the end.

Process finished with exit code 0

Either the program was started with Run instead of Debug, or no breakpoint sits on a line that runs.

FixClick the gutter for a red dot, then start with the bug icon.

Before
green Play arrow, no red dot
After
red dot on the line, bug icon

Compile messages appear in the Build window, runtime ones in the Run window. Line numbers will differ in your code.
