Hotel Operations 3

Same method name, different parameters: Employee punches the clock two ways, and a new Hotel books rooms.

What you are building

Your hotel-operations-2 code in a new project, grown two ways. Employee gets punchIn() and punchOut() with no parameters, next to the int versions: they read the current time themselves. A new Hotel class tracks suites and basic rooms, books them, and works out what is still free.

No setters on Hotel, today only, no menu or user input. The workbook says continue in hotel-operations; here every exercise gets its own project and repository.

Where people get stuck

  • "method is already defined". Two methods with the same name need different parameter lists, not just different bodies.
  • "cannot find symbol LocalDateTime". It lives in java.time: add the import.
  • Available goes negative. bookRoom updated the count before checking there were enough rooms.
  • Available never changes. It was stored in a field. Work it out from the totals and the booked counts.
