Hotel Operations Tests

Your hotel classes, checked by code instead of by eye: JUnit tests for Room and Employee.

What you are building

A new project with your Hotel Operations 3 code, plus JUnit and two test classes. RoomTest checks what checkIn, checkOut and cleanRoom do to a room. EmployeeTest checks that punchIn and punchOut with an int time add up the hours correctly.

Your classes do not change and main is not involved. The punch methods that read the clock (LocalDateTime) are not tested: their result changes every run.

What a finished run looks like

Run tool window
✓ Tests passed: 6 of 6 tests ✓ RoomTest ✓ checkIn_... ✓ checkOut_... ✓ cleanRoom_... ✓ EmployeeTest ✓ punchOut_...

Yours will differ: your test names, your count. What matters is every line green.

Where people get stuck

  • @Test and Assertions stay red. The pom changed but Maven was not reloaded. Press the Maven reload icon.
  • The test cannot see Room. The test class sits outside src/test/java/com/pluralsight, so its package does not match.
  • "No tests found". A test method is missing its @Test line.
  • A test passes one run and fails the next. It uses a clock-based punch method. Test the int versions only.

The one idea

A test sets up an object, calls one method, and asserts what changed. Green means your class does what you said it does.
