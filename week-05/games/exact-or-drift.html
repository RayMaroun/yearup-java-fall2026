double = binary, most decimals are close, not exact · BigDecimal from a String = exact, keeps its decimal places · every BigDecimal method returns a new object

The one idea

A double stores the nearest binary value, so cents drift; a BigDecimal built from a String stores the decimal exactly. Build it from a String, assign every result (total = total.add(price);), round with setScale(2, RoundingMode.HALF_UP), and compare with compareTo, never equals.
