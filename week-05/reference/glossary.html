Classes and objects

Object

One thing in your program that knows some data and can do some work with it.

Person person1 = new Person("Raymond", "Maroun", 55);See it: Thinking in Objects

Class

The blueprint that says which fields an object holds and which methods it has; it lives in a .java file of the same name.

public class Person { ... }See it: Thinking in Objects

Instance

One object built from a class with new; creating it is called instantiating.

Car car1 = new Car("Toyota", "Prius");See it: Thinking in Objects

Field

A variable declared in the class, outside every method, that each object keeps its own value of.

private String firstName;See it: Thinking in Objects

Constructor

The code that new runs once to set up an object; it has the class name and no return type.

public Person(String firstName, String lastName, int age) { ... }See it: The Constructor

this

Means "this object", so this.age is the field while age alone is the parameter with the same name.

this.age = age;See it: The Constructor

Encapsulation and access

Encapsulation

Keeping an object's fields private and letting the outside world in only through the methods you choose.

person1.age // error: age has private access in PersonSee it: Encapsulation

Getter

A public method that hands back the value of a private field and does nothing else.

public int getAge() { return age; }See it: Encapsulation

Setter

A public method that stores a new value in a private field and does nothing else.

public void setAge(int age) { this.age = age; }See it: Encapsulation

Derived getter

A getter that calculates its value from other fields instead of reading a field of its own.

public String getFullName() { return firstName + " " + lastName; }See it: Derived Getters

Boolean getter

A getter that answers a true or false question, named is... instead of get...

public boolean isAdult() { return age >= 18; }See it: Boolean Getters

Access modifier

The word in front of a class, field or method (public, private, or none) that decides who can use it.

private int age; public int getAge()See it: Default Access

Package-private

What you get with no access modifier at all: visible inside the same package, hidden from every other package.

String name; // no modifierSee it: Default Access

Methods and overloading

Method

A function inside a class that does work, often reading or changing the object's own fields.

person1.work(5); // energy goes downSee it: Methods Change State

Parameter vs argument

A parameter is the variable a method declares, and an argument is the value you pass in when you call it.

work(int hours) // parameter work(5) // argumentSee it: Method Overloading

Method signature

The name of a method plus the type of each parameter, in order; the return type is not part of it.

foo(int x, String s) // signature foo_int_StringSee it: Method Overloading

Overloading

Two or more methods or constructors with the same name and different signatures, where the arguments decide which one runs.

new Person(55, "Ray") new Person("Sensei", 33)See it: Method Overloading

Cohesion

How closely the fields and methods inside one class belong together; the goal is high cohesion, one class with one job.

See it: Cohesion

Unit testing

Unit test

A small automated test that checks one method of one class on its own and runs in milliseconds.

public class CarTest { ... }See it: The Testing Pyramid

JUnit

The framework Java developers use to write and run unit tests; JUnit 5 lives in org.junit.jupiter.

import org.junit.jupiter.api.Test;See it: Arrange, Act, Assert

Assertion

The check at the end of a test that passes when the actual value matches the expected one and fails otherwise.

assertEquals(expectedSpeed, actualSpeed);See it: Arrange, Act, Assert

Arrange, Act, Assert

The three parts of a test: set up the objects, call the method under test, then check the result.

// arrange // act // assertSee it: Arrange, Act, Assert

Test pyramid

The picture of a healthy test suite: many fast unit tests, fewer integration tests, and the fewest slow end to end tests.

See it: The Testing Pyramid

BigDecimal

BigDecimal

A java.math object that holds a decimal value exactly, used for money where a double would drift.

BigDecimal price = new BigDecimal("19.99");See it: Why Doubles Drift

RoundingMode

Tells BigDecimal how to round when it drops digits, such as HALF_UP; setScale and divide need one.

import java.math.RoundingMode;See it: BigDecimal Operations

Scale

The number of digits after the decimal point of a BigDecimal, set with setScale and a rounding mode.

taxed.setScale(2, RoundingMode.HALF_UP)See it: BigDecimal Operations

Immutable

A BigDecimal never changes; add, subtract, multiply and divide return a new one that you must assign.

cartTotal = cartTotal.add(price);See it: BigDecimal Operations

compareTo()

Compares two BigDecimal values and returns a negative number, 0 or a positive number; equals() says 5.0 and 5.00 differ, compareTo says they are equal.

five.compareTo(fiveHundredths) // 0See it: BigDecimal Operations

Static

static

Marks a field or method that belongs to the class itself, one copy shared by every object, called on the class name, and a static method cannot use this.

private static String schoolName = "Greenwood High";See it: Instance vs Static

Instance member

A field or method without static, so each object has its own copy and you need an object to use it.

alice.printDetails();See it: Instance vs Static

Utility class

A class made only of static methods and variables, used without new, like Java's Math.

Math.pow(5, 2) // 25.0See it: Utility Classes

Classes working together

Has-a relationship

One class keeps another class as a field, so it can call that object's methods.

private Player captain; // a Team has-a PlayerSee it: Has-A and Class Communication

Composition

Building a bigger object out of smaller ones it holds as fields, which is how a has-a relationship is coded.

team.printRoster(); // calls getName() on each PlayerSee it: Has-A and Class Communication

Class diagram (UML)

A drawing with one box per class listing its fields and methods, and lines between the classes that work together.
