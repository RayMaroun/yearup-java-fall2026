Common Errors

The messages you will meet this week, word for word, and the quiet bugs that print no message at all. Read the first line of the message: it usually names the fix.

Show
Compile

Reaching a private field from outside

See it
java: age has private access in Person

The field is private, so only code inside Person can touch it. Main is outside the class.

FixRead it through the getter. If outside code must change it, add a setter or a method that does the change.

Before
System.out.println(instructor.age);
After
System.out.println(instructor.getAge());
Compile

No constructor matches the new

See it
java: constructor Learner in class Learner cannot be applied to given types;
  required: String,int
  found:    String
  reason: actual and formal argument lists differ in length

The only constructor needs a name and a grade, and the call passes a name only. With several constructors the message reads no suitable constructor found for Learner(String) and lists each one it tried.

FixPass what required lists, in that order, or add an overload that takes what you have.

Before
Learner alice = new Learner("Alice");
After
Learner alice = new Learner("Alice", 10);
Compile

A field used from static main

See it
java: non-static variable lastName cannot be referenced from a static context

main is static: it runs with no object. A field without static lives inside an object, so there is no lastName for main to read.

FixMake the field static if it belongs to the class, or create an object and read it from there.

Before
public String lastName = "Maroun";

public static void main(String[] args) {
    System.out.println(lastName);
}
After
public static String lastName = "Maroun";

public static void main(String[] args) {
    System.out.println(lastName);
}
Compile

A method called from static main

See it
java: non-static method greetEveryone() cannot be referenced from a static context

Same rule for methods: greetEveryone has no static, so it needs an object, and main has none.

FixAdd static to a helper that uses no fields of an object.

Before
public void greetEveryone() {
    System.out.println("Hello everyone!");
}
After
public static void greetEveryone() {
    System.out.println("Hello everyone!");
}
Compile

An instance method on the class name

See it
java: non-static method printDetails() cannot be referenced from a static context

printDetails prints one learner's name and grade. Learner.printDetails() does not say which learner, so Java refuses it.

FixCall it on an object. The class name goes in front of static methods only, like Learner.changeSchool("Lakeside Academy").

Before
Learner.printDetails();
After
alice.printDetails();
Runtime

setScale without a rounding mode

See it
Exception in thread "main" java.lang.ArithmeticException: Rounding necessary
	at java.base/java.math.BigDecimal.commonNeedIncrement(BigDecimal.java:4721)
	...
	at com.pluralsight.Main.main(Main.java:9)

19.995 has three decimals. Going to two means rounding, and with no rounding mode BigDecimal will not guess which way.

FixName the rounding mode, import java.math.RoundingMode, and assign the result.

Before
BigDecimal price = new BigDecimal("19.995");
price = price.setScale(2);
After
BigDecimal price = new BigDecimal("19.995");
price = price.setScale(2, RoundingMode.HALF_UP);
// 20.00
Runtime

divide without a scale

See it
Exception in thread "main" java.lang.ArithmeticException: Non-terminating decimal expansion; no exact representable decimal result.
	at java.base/java.math.BigDecimal.divide(BigDecimal.java:1780)
	...
	at com.pluralsight.Main.main(Main.java:11)

100 split three ways is 33.333..., forever. BigDecimal is exact, so it stops rather than write an endless number.

FixTell divide how many decimals to keep and how to round.

Before
BigDecimal bill = new BigDecimal("100.00");
BigDecimal share = bill.divide(new BigDecimal("3"));
After
BigDecimal bill = new BigDecimal("100.00");
BigDecimal share = bill.divide(new BigDecimal("3"),
        2, RoundingMode.HALF_UP);
// 33.33
Runtime

equals says 5.0 and 5.00 differ

See it

No error. Console:

false

equals on a BigDecimal checks the value and the number of decimals. 5.0 has one, 5.00 has two, so they are not equal to it.

FixCompare amounts with compareTo: it returns 0 when the values are the same, whatever the decimals.

Before
BigDecimal paid = new BigDecimal("5.0");
BigDecimal due = new BigDecimal("5.00");
System.out.println(paid.equals(due));
After
BigDecimal paid = new BigDecimal("5.0");
BigDecimal due = new BigDecimal("5.00");
System.out.println(paid.compareTo(due) == 0);
// true
Runtime

new BigDecimal from a double

See it

No error. Console:

0.1000000000000000055511151231257827021181583404541015625

The double 0.1 is already an approximation in binary. new BigDecimal(0.1) copies that approximation exactly, every digit of it.

FixBuild from a String, or with BigDecimal.valueOf from a whole number.

Before
BigDecimal tip = new BigDecimal(0.1);
After
BigDecimal tip = new BigDecimal("0.10");
Runtime

add without assigning the result

See it

No error. Console:

Total: 0.00

A BigDecimal never changes. add returns a new object with the sum, and the line throws it away, so total stays where it was.

FixAssign the result back. The same goes for subtract, multiply, divide and setScale.

Before
BigDecimal total = new BigDecimal("0.00");
total.add(new BigDecimal("4.50"));
After
BigDecimal total = new BigDecimal("0.00");
total = total.add(new BigDecimal("4.50"));
// Total: 4.50
Runtime

A field the constructor never set

See it
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.toUpperCase()" because the return value of "com.pluralsight.Person.getLastName()" is null
	at com.pluralsight.Main.main(Main.java:14)

This constructor takes an age and a first name only, so lastName is still null, and you cannot call a method on nothing.

FixGive every field a value in every constructor, even a default one.

Before
public Person(int age, String firstName) {
    this.age = age;
    this.firstName = firstName;
}
After
public Person(int age, String firstName) {
    this.age = age;
    this.firstName = firstName;
    this.lastName = "";
}
Testing

JUnit is not in the project

See it
java: package org.junit.jupiter.api does not exist
java: cannot find symbol
  symbol:   class Test
  location: class CarTest

The test imports JUnit, but pom.xml has no JUnit dependency, or IntelliJ has not loaded it yet.

FixAdd the dependency (or click Fix when IntelliJ creates the test), then press Load Maven Changes, the small Maven icon that appears over pom.xml.

Before
<dependencies>
</dependencies>
After
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>5.10.2</version>
    <scope>test</scope>
</dependency>
Testing

A test class in src/main

See it
java: package org.junit.jupiter.api does not exist

The dependency is there, but its test scope makes JUnit visible only under src/test/java. A test file in src/main/java cannot see it.

FixMove the test to the same package under src/test/java. Navigate > Test (Ctrl+Shift+T, Cmd+Shift+T on a Mac) creates it in the right place.

Before
src/main/java/com/pluralsight/CarTest.java
After
src/test/java/com/pluralsight/CarTest.java
Testing

A getter that returns the wrong field

See it

Compiles and runs. The test fails:

org.opentest4j.AssertionFailedError: expected: <Bugatti> but was: <Chevron>

Both fields are Strings, so the compiler is happy, but getMake hands back the model. This is the kind of slip a unit test is for.

FixReturn the field the getter is named after. Generate > Getter writes it for you.

Before
public String getMake() {
    return model;
}
After
public String getMake() {
    return make;
}

Compile messages appear in the Build window, runtime ones in the Run window, test failures in the Run window under the test name. Line numbers will differ in your code.
