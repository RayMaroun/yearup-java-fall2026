An interface box 6a · 1-1

the box
the markWrite «interface» above the name. That is the only thing that tells it apart from a class box.
two bandsAn interface has no attributes, so the box has the name band and the methods band.
abstract methodsWritten in italics: they have no body. Every class that implements the interface has to write them.
default methodsWritten upright, like any method with a body. A class may override them or not.
signsEvery method is +, public, without you writing it in the Java.

Two arrows, two meanings 6a · 2-1

side by side
solid, hollow triangleA child class extends a parent class: a Dog is an Animal. One parent only.
dashed, hollow triangleA class implements an interface: a Turtle can do what IMovable lists. As many as the class needs.
directionBoth arrows start at the class and end with the triangle at the parent or the interface.
several interfacesOne dashed arrow for each interface the class implements.

Has-a lines 6a · 1-2

two kinds
associationA plain line: one class knows the other, such as a Robot and its Dock. No arrowhead.
aggregationA line with a hollow diamond on the owner's side: a Fleet holds Robots, and a Robot can still exist without the Fleet.
in JavaBoth are a field in the class: private Dock dock; or private List<Robot> robots;. The diamond is on the class that has the field.
is-a or has-aTriangle: is a, one class is a kind of the other. Line or diamond: has a, one class holds the other.

How many 6a · 1-2

whereWrite the number at the end of the line, next to the class it counts. 1 at the Fleet and * at the Robot reads: one Fleet holds many Robots.
in Java0..1 is a field that may be null. * is a list or an array.

Static underlined, abstract in italics 6a · 1-2, 2-2

two boxes
staticUnderline the attribute or method that belongs to the class, not to each object. In Java: private static int count;
abstractItalics for an abstract class name and for an abstract method, as on Week 6. In an interface, the abstract methods are italic by the same rule.
on paperDraw a line under static members by hand and slant the abstract ones.

A whole design on one page 6a · 2-1

the design
1 · interfacesIMovable and ICleaner at the top, each with «interface». Both have a default print(), upright.
2 · dashedRobot implements IMovable. RobotVacuum implements ICleaner.
3 · solidRobotVacuum extends Robot, so it also is an IMovable and does not repeat what Robot has. Robot is abstract, so its name and describe() are italic.
4 · diamondA Fleet holds many Robots: 1 at the Fleet, * at the Robot.
5 · plain lineA RobotVacuum has at most one Dock: 1 and 0..1.
6 · staticcount and getCount() are underlined in Fleet.
in Javapublic interface IMovable { Point move(int x, int y); void goHome(); default void print() { ... } } public interface ICleaner { void clean(); default void print() { ... } } public abstract class Robot implements IMovable { public abstract String describe(); ... } public class RobotVacuum extends Robot implements ICleaner { ... } public class Fleet { private List<Robot> robots; private static int count; ... }
noteRobotVacuum gets one default print() through Robot and another from ICleaner, so it overrides print(), and the method is listed in its box.

Common slips 6a · 2-1

SlipFix
A solid line to an interfaceA class implements: use the dashed line.

An attributes band in an interfaceLeave it out: an interface lists methods.
The diamond at the partThe diamond sits on the owner, the class that holds the others.
