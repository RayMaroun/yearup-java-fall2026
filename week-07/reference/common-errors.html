Week 7 · Reference

Common Errors

The messages you will meet this week, word for word, and the quiet bugs that print no message at all. Read the first line of the message: it usually names the fix. In IntelliJ each compile message starts with java:.

Show
Compile

A class does not write an interface method

See it
java: Speaker is not abstract and does not override abstract method play(String) in Playable

Speaker says implements Playable but never writes play(String). Every abstract method of the interface must be written in the class. The same message appears when the name or the parameters differ, because then it is a different method.

FixWrite the method with the exact name, parameters and return type from the interface, and put @Override above it so a typo is caught too.

Before
public class Speaker implements Playable {
    public void stop() { ... }
}
After
public class Speaker implements Playable {
    @Override
    public void play(String song) { ... }
    @Override
    public void stop() { ... }
}
Compile

The method is not public

See it
java: charge() in Radio cannot implement charge() in Chargeable
  attempting to assign weaker access privileges; was public

Methods of an interface are public without saying so. A method that implements one cannot be less open, so the missing public in the class is the error.

FixAdd public to the method in the class.

Before
class Radio implements Chargeable {
    void charge() { ... }
}
After
class Radio implements Chargeable {
    public void charge() { ... }
}
Compile

Two interfaces with the same default method

See it
java: types Playable and Chargeable are incompatible;
  class Phone inherits unrelated defaults for print() from types Playable and Chargeable

Both interfaces have a default print() and Phone implements both. Java cannot choose, so it makes you choose. The error points at the class line, not at a method.

FixOverride print() in the class. Inside it, call one default with InterfaceName.super.print(), call both, or write your own text.

Before
public class Phone implements Playable, Chargeable {
    // no print() here
}
After
public class Phone implements Playable, Chargeable {
    @Override
    public void print() {
        Playable.super.print();
    }
}
Compile

An interface cannot be built with new

See it
java: Playable is abstract; cannot be instantiated

An interface only lists features, so there is no object to create from it. You build an object of a class that implements it.

FixUse new with a class, and keep the interface as the type of the variable.

Before
Playable player = new Playable();
After
Playable player = new Speaker("Boom");
Compile

The variable's type does not have that method

See it
java: cannot find symbol
  symbol:   method charge()
  location: variable p of type Playable

The variable is a Playable, so it only sees the methods Playable declares, even though the object is a Phone that can charge.

FixAsk with instanceof Chargeable and cast to the interface that has the method, or keep a variable of the type that declares it.

Before
Playable p = new Phone("Pocket");
p.charge();
After
if (p instanceof Chargeable) {
    ((Chargeable) p).charge();
}
Compile

A LinkedList in an ArrayList variable

See it
java: incompatible types: cannot infer type arguments for LinkedList<>
    reason: no instance(s) of type variable(s) E exist so that LinkedList<E> conforms to ArrayList<String>
  where E is a type-variable:
    E extends Object declared in class LinkedList

ArrayList and LinkedList are two different classes. Only the interface List is common to both, so only a List variable can hold either one.

FixDeclare the variable with the interface type.

Before
ArrayList<String> names = new ArrayList<>();
names = new LinkedList<>();
After
List<String> names = new ArrayList<>();
names = new LinkedList<>();
Compile

A type argument outside the bound

See it
java: type argument Integer is not within bounds of type-variable T
  where T is a type-variable:
    T extends Musician declared in class Duet
java: cannot infer type arguments for Duet<>
  reason: inference variable T has incompatible bounds
    lower bounds: Musician
    lower bounds: Integer

Duet<T extends Musician> only accepts Musician or a child of it. Integer is neither. A second message about the same line follows; fix the first and both go away.

FixUse a type that fits the bound.

Before
Duet<Integer> twoNumbers = new Duet<>(15, 32);
After
Duet<Musician> duet = new Duet<>(new Cellist("Leo", "Cello"),
                                  new Violinist("Maya", "Violin"));
Compile

A primitive as a type argument

See it
java: unexpected type
  required: reference
  found:    int

Generics take objects, and int is a primitive. The message says it wants a reference type.

FixUse the wrapper type: Integer for int, Double for double, Boolean for boolean, Character for char.

Before
List<int> numbers = new ArrayList<>();
After
List<Integer> numbers = new ArrayList<>();
Compile

An unbounded T calling a method

See it
java: cannot find symbol
  symbol:   method perform()
  location: variable left of type T
  where T is a type-variable:
    T extends Object declared in class Pair

With no bound, T could be any type, even Integer, and Integer has no perform(). The compiler only allows what every possible T has.

FixBound the type so every T has the method: T extends Musician.

Before
public class Pair<T> {
    void perform() { left.perform(); }
}
After
public class Duet<T extends Musician> {
    void perform() { left.perform(); }
}
Compile

Two different types in one Pair

See it
java: incompatible types: cannot infer type arguments for Pair<>
    reason: inference variable T has incompatible bounds
      equality constraints: Integer
      lower bounds: String,Integer
  where T is a type-variable:
    T extends Object declared in class Pair

Pair<Integer> fixed T to Integer, and "Me" is a String. One type parameter means one type for both values.

FixUse the same type for both values.

Before
Pair<Integer> p = new Pair<>(63, "Me");
After
Pair<Integer> p = new Pair<>(63, 65);
Compile

Sorting a class that is not Comparable

See it
java: no suitable method found for sort(List<Song>)
    method Collections.<T#1>sort(List<T#1>) is not applicable
      (inference variable T#1 has incompatible bounds
        equality constraints: Song
        lower bounds: Comparable<? super T#1>)
    method Collections.<T#2>sort(List<T#2>,Comparator<? super T#2>) is not applicable
      (cannot infer type-variable(s) T#2
        (actual and formal argument lists differ in length))

Collections.sort needs to know how two Songs compare, and Song does not implement Comparable. The long message is two failed tries: the second one is the version that takes a Comparator.

FixMake the class implement Comparable<Song> and write compareTo.

Before
public class Song { ... }
Collections.sort(songs);
After
public class Song implements Comparable<Song> {
    @Override
    public int compareTo(Song other) { ... }
}
Compile

A lambda changes a local variable

See it
java: local variables referenced from a lambda expression must be final or effectively final

The lambda runs later, possibly somewhere else, so it may read a local variable only if that variable never changes. total += n changes it.

FixDo not change a local variable inside a lambda. Compute the total with reduce, or loop with a normal for loop.

Before
int total = 0;
numbers.forEach(n -> total += n);
After
int total = numbers.stream()
    .reduce(0, (sum, n) -> sum + n);
Compile

A block lambda with an expression and no return

See it
java: not a statement

With braces, the body is a list of statements, and n > 2; is not a statement. In a block, a lambda that must give a value needs return.

FixDrop the braces for one expression, or keep them and write return.

Before
nums.stream().filter(n -> { n > 2; })
After
nums.stream().filter(n -> n > 2)

nums.stream().filter(n -> { return n > 2; })
Compile

count() stored in an int

See it
java: incompatible types: possible lossy conversion from long to int

count() returns a long, which is bigger than an int.

FixStore it in a long.

Before
int howMany = titles.stream()
    .filter(t -> t.contains("Halloween")).count();
After
long howMany = titles.stream()
    .filter(t -> t.contains("Halloween")).count();
Compile

reduce result in the wrong type

See it
java: incompatible types: Integer cannot be converted to String

reduce gives back the same type as the elements. A stream of Integer reduces to an Integer, not a String.

FixStore the result in the element type, then convert it if you need text.

Before
String s = nums.stream().reduce(0, (x, y) -> x + y);
After
int sum = nums.stream().reduce(0, (x, y) -> x + y);
String s = String.valueOf(sum);
Runtime

A stream used twice

See it
Exception in thread "main" java.lang.IllegalStateException: stream has already been operated upon or closed
	at java.base/java.util.stream.AbstractPipeline.evaluate(AbstractPipeline.java:229)
	at java.base/java.util.stream.ReferencePipeline.forEach(ReferencePipeline.java:596)
	at Main.main(Main.java:7)

count() ended the stream. A stream flows once, so the next call on the same variable throws. The last line of the trace, the one that starts with at Main.main, is your own line: the second use.

FixDo not keep a stream in a variable. Start a new stream from the collection each time.

Before
Stream<String> longWords = words.stream().filter(...);
longWords.count();
longWords.forEach(System.out::println);
After
words.stream().filter(...).count();
words.stream().filter(...).forEach(System.out::println);
Runtime

A cast to an interface the object does not implement

See it
Exception in thread "main" java.lang.ClassCastException: class Speaker cannot be cast to class Chargeable (Speaker and Chargeable are in unnamed module of loader 'app')
	at Main.main(Main.java:13)

The code compiled, because a cast to an interface is allowed. At run time the object is a Speaker, and Speaker does not implement Chargeable.

FixAsk first with instanceof, and cast only when it is true.

Before
Chargeable c = (Chargeable) thing;
After
if (thing instanceof Chargeable) {
    Chargeable c = (Chargeable) thing;
}
Runtime

sorted() on a class that is not Comparable

See it
Exception in thread "main" java.lang.ClassCastException: class Song cannot be cast to class java.lang.Comparable (Song is in unnamed module of loader 'app'; java.lang.Comparable is in module java.base of loader 'bootstrap')
	at java.base/java.util.Comparators$NaturalOrderComparator.compare(Comparators.java:47)
	...
	at Main.main(Main.java:7)

Unlike Collections.sort, the stream's sorted() compiles anyway and fails when it runs, the first time it has to compare two Songs.

FixImplement Comparable<Song> in the class.

Before
songs.stream().sorted().collect(Collectors.toList());
After
public class Song implements Comparable<Song> { ... }
Runtime

Adding to the list that toList() gave back

See it
Exception in thread "main" java.lang.UnsupportedOperationException
	at java.base/java.util.ImmutableCollections.uoe(ImmutableCollections.java:142)
	at java.base/java.util.ImmutableCollections$AbstractImmutableCollection.add(ImmutableCollections.java:147)
	at Main.main(Main.java:7)

The list from .toList() is read-only: add, remove and set all throw. Collectors.toList() is the form the workbook teaches.

FixDo not change that list, or copy it into a new ArrayList first.

Before
List<String> fixed = titles.stream().filter(...).toList();
fixed.add("Twister");
After
List<String> list = titles.stream().filter(...)
    .collect(Collectors.toList());
list.add("Twister");
Quiet bug

A pipeline with no terminal operation

See it
(no message) the program prints:
done

filter and map only describe the steps. Nothing runs, not even the println inside the lambda, until a terminal operation such as forEach, count or collect ends the stream.

FixEnd every pipeline with a terminal operation, and keep its result.

Before
titles.stream().filter(t -> { System.out.println("checking " + t); return t.length() > 5; });
System.out.println("done");
After
titles.stream().filter(t -> t.length() > 5).forEach(System.out::println);
Quiet bug

map thrown away, the list unchanged

See it
(no message) the program prints:
[alice, bob]

A stream never changes its source. The mapped values went nowhere because nothing collected them, and names is exactly as it was.

FixCollect into a new list and use that one.

Before
names.stream().map(n -> n.toUpperCase());
System.out.println(names);
After
List<String> upper = names.stream()
    .map(n -> n.toUpperCase())
    .collect(Collectors.toList());
System.out.println(upper);

Messages were produced by compiling and running small samples on Java 17. The line numbers in your own message will differ, and a long stack trace is shortened to the lines that matter.
