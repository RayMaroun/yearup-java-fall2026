Week 4 · Reference · Capstone guide

Demo Day

Ten minutes, six parts, one scenario you have typed before. Read the guide, then tick the list before you start.

Each learner gets 10 minutes on demo day, Friday, November 6. Run through the screens, show one piece of code you are proud of, take questions.

The ten minutes

1 min1 min2 min2 min3 min1 min
0:005:0010:00

  1. Introduction

    • Introduce yourself.
    • Provide a brief overview of the project.
    1 min

  2. Challenges & Solutions

    • Discuss a significant challenge you faced during the project.
    • Explain how you overcame it and any lessons learned.
    1 min

  3. GitHub Repository Review

    • Navigate to the repository.
    • Show and discuss the commit history, emphasizing major milestones or changes.
    • Open and discuss the README file, highlighting its contents and structure.
    • Review the GitHub project board, explaining its layout, tasks, and progression.
    2 min

  4. Code Deep Dive

    • Start with a high-level explanation of the code structure.
    • Delve into specific sections of the code, highlighting main features and functions.
    2 min

  5. Live Demo

    • Run the program.
    • Conduct a brief demonstration of the main features, ensuring to engage the audience.
    3 min

  6. Q&A Session

    • Open the floor to questions from the audience.
    • Address each question confidently and clearly.
    1 min

From Raymond: This is to help you during the presentation. Feel free to change the order of the steps however you like.

The minutes are a budget, not a rule. The live demo is the part people remember, so protect its three.

Before you presentTick each one on the day. Nothing is saved; the list is clean every time you open it.

Six things to check. Tick them as you go.

What Raymond may askPlain questions about your own project. Know where the answer lives in your code before Friday.

  • Why is a payment stored as a negative number?
  • What happens if transactions.csv is missing?
  • Show me where the ledger is sorted newest first.
  • Which part was hardest and what did you change?
  • What would you add with one more day?

The one idea

A demo is a rehearsed walk, not a tour of everything. One scenario typed from memory, one piece of code you can explain without reading it, and the rest of the ten minutes is yours.
