Build Guide

Thirteen steps, in the order to build them. Each step says what to do, what it looks like when it works, what usually goes wrong, and what to commit. Tick a step when its "done looks like" is true on your screen.

Before you startRead the PDF in Brightspace twice. Open the Requirements Checklist next to this page.
Work in this orderEvery step uses the one before it. Skipping ahead is how you end up with a report that cannot read the file.
Commit after every stepOne commit per step is the "commit history" the spec asks for, and it saves your work when something breaks.
Stuck for 20 minutes?Bring the step number and what your screen shows to office hours. "Step 6, the line goes in the file but the next run does not load it" gets you an answer fast.

    3

    The Transaction class

    One Line, One Object

    Do

    1. Read one line of the file: date|time|description|vendor|amount. One line is one object, so the class has five fields, one per piece.
    2. Pick the type each field needs later: the date is a LocalDate (the reports will ask "is it after this day?"), the time a LocalTime, description and vendor are String, the amount a double (the ledger will compare it with zero).
    3. Write the constructor that takes all five, and a getter for each field. Nothing else yet.

    Done looks like

    The project compiles. The red in FinancialTracker is gone. Running it shows the Home menu, and the letters do nothing yet.

    Watch out

    • Amount as a String is the mistake that breaks steps 7, 9 and 10. Make it a double now.
    • Same name and same package as the starter expects: Transaction in com.pluralsight.

    Add Transaction class
    4

    Load the file at start

    Load Then AppendFrom Lines to Objects

    Do

    1. If transactions.csv does not exist, create it empty. The spec says the app creates the file.
    2. Open it with a BufferedReader. Loop: read a line, stop when it is null.
    3. For each line: split on the pipe, parse the date, the time and the amount, build a Transaction, add it to the list.
    4. Wrap the file work in try and catch. Close the reader.

    Done looks like

    A temporary print of the list size after loading says 21 with the starter file. Delete the file, run again: it is created empty and the app still starts.

    Watch out

    • The pipe is special in split. Use "\\|", or every character becomes its own piece.
    • Dates parse only when the text is exactly yyyy-MM-dd. A space at the end of a line breaks it: trim.
    • The file path is relative to the project root, which is where IntelliJ runs the app.

    Commit

    Load transactions from transactions.csv

    Home screen loop

    Menu Flow Map

    Do

    1. Print the four options exactly as the spec writes them: D) Add Deposit, P) Make Payment (Debit), L) Ledger, X) Exit.
    2. Read one line, trim it, make it upper case so d and D both work.
    3. A loop that keeps showing the menu until X. Each letter is one case; an unknown letter prints a short message and the menu comes back.

    Done looks like

    The menu prints, L prints "Ledger" (a placeholder for now) and the menu prints again, q says "not an option" and the menu prints again, X ends the program.

    Watch out

    • Mixing nextInt and nextLine on the same Scanner eats inputs. Read everything with nextLine and parse what needs a number.
    • One Scanner for the whole app, passed into the methods. Two Scanners on System.in fight each other.

    6

    Add a deposit

    Deposit or PaymentLoad Then Append

    Do

    1. Ask for the date and time as one text in the format yyyy-MM-dd HH:mm:ss, then the description, the vendor, the amount.
    2. Parse the date and time with a formatter for that pattern. Parse the amount; if it is not positive, say so and ask again.
    3. Build the Transaction, add it to the list, and append one line to the file in the exact file format, amount with two decimals.

    Done looks like

    Open transactions.csv after a deposit: one new line at the bottom, same format as the others, nothing else changed. Run the app again and the count from step 4 is one higher.

    Watch out

    • The writer must be in append mode, or the file is wiped and only the new line remains. Step 4's count tells you at once.
    • Write a line break after the line, or the next deposit glues to this one.
    • %.2f for the amount. 4400.0 in the file is not the format.

    Make a payment

    Deposit or Payment

    Do

    1. Same questions as the deposit. The user types a positive amount.
    2. Before storing, make the amount negative. That sign is what makes it a payment; there is no other field for it.
    3. Same append to the file. If steps 6 and 7 share one method with a flag, better.

    Done looks like

    The new line in the file ends with a minus amount, for example |-48.30, and loads back as a negative number next run.

    Watch out

    • Do not ask the user to type the minus. If they do anyway, reject it like any non-positive amount.

    8

    Ledger menu and All

    Menu Flow Map

    Do

    1. A second loop like the Home one, with A) All, D) Deposits, P) Payments, R) Reports, H) Home. H ends this loop and the Home menu shows again.
    2. A prints every transaction, one per line, in columns: date, time, description, vendor, amount. Use printf with widths so the columns line up.
    3. Newest first. Sort the list by date, then by time, descending, before printing. Or walk the list from the last index down to zero if your file is always in order, but sorting is safer.

    Done looks like

    The top line of A is the latest date in the file (with the starter file, 2026-11-03). Columns line up. H brings the Home menu back.

    Watch out

    • "Newest first" is in the spec and is the first thing Raymond checks. Oldest first is the most common miss.
    • Negative amounts need room for the sign in the column width.

    Commit

    Ledger menu, all entries newest first

    Deposits and payments

    Deposit or Payment

    Do

    1. Same printing as All, with one test in the loop: amount greater than zero for Deposits, less than zero for Payments.
    2. Put the "print one transaction as a row" code in one method and call it from all three, so the columns never drift apart.

    Done looks like

    D shows only positive amounts, P only negative ones, both newest first, and together they add up to the lines of A.

    Watch out

    • If both lists look the same, the amount is probably still a String. Back to step 3.

    Ledger: deposits and payments
    10

    Reports menu and the four date reports

    Date Range Reports

    Do

    1. A third loop: 1) Month To Date, 2) Previous Month, 3) Year To Date, 4) Previous Year, 5) Search by Vendor, 0) Back. 0 ends this loop and the Ledger menu shows again.
    2. Every date report is the same question: is the transaction date between a start and an end, both included? Write one method that takes a start and an end and prints the matching rows. The four reports only compute the two dates and call it.
    3. The dates, from LocalDate.now(): Month To Date is the first of this month to today. Previous Month is the first to the last day of last month. Year To Date is January 1 to today. Previous Year is January 1 to December 31 of last year.

    Done looks like

    With the starter file in the first week of November: Month To Date shows the two November rows, Previous Month the three October rows, Year To Date every 2026 row, Previous Year every 2025 row. An empty result prints a message, not nothing.

    Watch out

    • isAfter and isBefore exclude the boundary day. A transaction on the first of the month must count, so test "not before start and not after end".
    • Previous Month in January is December of last year. minusMonths(1) handles that; subtracting one from the month number does not.
    • Do not compare dates as text.

    Commit

    12

    Custom search (bonus)

    Custom Search Pipelineonly after 1 to 11 work

    Do

    1. Add 6) Custom Search to the Reports menu. Ask for five values in this order: start date, end date, description, vendor, amount. Enter with nothing typed means "no filter".
    2. One loop over the list. For each value: if the user typed something and the row does not match it, skip the row. A blank value skips the test, not the row.
    3. Dates and amount need parsing only when they are not blank; keep them as null otherwise.

    Done looks like

    All five blank prints every row. Vendor only prints the same as step 11. Start and end dates only prints the same as a date report with those dates. Combined filters narrow the rows further, never widen them.

    Watch out

    • Parsing a blank date throws. Check for blank before parsing.
    • Filters combine with AND. A row has to pass every filter that was given.
