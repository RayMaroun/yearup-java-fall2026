The Commit Message

A subject line that says what changed, a blank line, then bullets that say what you did.

What you type in the IntelliJ commit box

feat: add month to date report (empty line, press Enter twice) - Filter transactions from the first of the month to today - Print them newest first in the ledger format - Show a message when the month has no transactions

type:

What kind of change. One of the five below, lowercase, with the colon.

subject

What changed, as an order: add, fix, show, remove, rename. Under 50 characters, no period. Not "added", not "update", not "stuff".

blank line

Not optional. Without it Git glues the bullets into the subject and GitHub shows one long title.

- bullets

What you did, one change per line, two to four lines. Skip them when the subject says it all, a README commit does not need bullets.

The five types you need

feat:

A feature the user can see: a menu option, a report, a search.

fix:

Something was wrong and now it is right.

docs:

README, comments, the board. No code behavior changes.

refactor:

Code moved or cleaned, same behavior: a method extracted, a name changed.

chore:

Project housekeeping: pom.xml, .gitignore, the csv sample file.

Six commits from this capstone

feat: add Transaction class with five fields - Fields date, time, description, vendor, amount - Constructor and getters, no setters
feat: load transactions from the csv at start - Create the file when it does not exist - Split each line on the pipe, one Transaction per line - Skip a line that does not have five fields

Someone reading the history on GitHub sees the subject lines only. The bullets open when they click one. Both should make sense without opening the code.

The one idea

type: what changed, a blank line, then bullets on what you did. feat, fix, docs, refactor or chore, a subject under 50 characters as an order, two to four bullets when the subject cannot hold it. One change per commit, at least four a day. "update", "final" and "asdf" are the lines Raymond will ask about.
