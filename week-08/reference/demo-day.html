Demo Day

Ten minutes, five parts, one order you have typed many times. Read the guide, then tick the list before you start.

Each learner is given 10 minutes on Demo Day, Friday, December 4. Present your application by running through its screens and scenarios, describe or show one interesting piece of code that you wrote, and answer questions if time permits.

You will be asked about your own code. Present code you can explain. Code you cannot explain counts against you.

The ten minutes

1 min2 min4 min2 min1 min
0:005:0010:00

  1. Introduction

    • Introduce yourself.
    • Name your shop and your option: the Deli, the Pizza, the Taco, or the shop you invented.
    • One sentence on what the application does for that shop.
    1 min

  2. Your design

    • Open your repository on GitHub and scroll to the README. Show the picture of your class diagram there.
    • Walk through it briefly: the main boxes and how they are connected.
    • Explain one design decision in a sentence: what you chose, and why you built it this way.
    2 min

  3. Live run

    One full order
    1. New Order.
    2. Add one main item (sandwich, pizza, taco or your own) with a premium topping and an extra portion of it, a regular topping, a sauce, and the special option.
    3. Add a drink.
    4. Add the third product (chips, garlic knots, chips and salsa, or your own).
    5. Checkout: show the order details and the total.
    6. Confirm, then open the new receipt file in the receipts folder.
    Then one edge case
    • An empty order at checkout, or a wrong input on a menu. Show the message and that the program asks again.
    4 min

  4. One interesting piece of code

    • Code that you wrote yourself, open in IntelliJ.
    • Say what it does, then walk it line by line.
    • Say why you wrote it this way.
    2 min

  5. Questions

    • Answer questions from the audience if time permits.
    • If you do not know, say so, and say where in your code you would look.
    1 min

The minutes are a budget, not a rule. The live run is the part people remember, so protect its four.

Submit before you present. Push your last commit first, then submit your repository link in Brightspace, not on the workshop form.

What you may be askedPlain questions about your own project. Know where the answer lives in your code before Friday.

  • Show me where the price of an extra portion is added.
  • What happens when someone presses Checkout on an empty order?
  • Where does the name of the receipt file come from?
  • Why did you build this part this way and not another way?
  • What changed in your diagram since Wednesday, and why?
  • Which part was hardest, and what would you add with one more day?

The one idea

A demo is a rehearsed walk, not a tour of everything. One full order typed from memory, one decision you can justify, one piece of your own code you can explain without reading it.
