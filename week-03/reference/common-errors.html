Common Errors

The messages you will meet this week, word for word. Read the first line of the message: it usually names the fix.

Show
Compile

Reading a file outside try

See it
java: unreported exception IOException; must be caught or declared to be thrown

readLine() can fail, so Java makes you plan for it. The new FileReader line gives the same message with FileNotFoundException.

FixPut the reader and the loop inside try, with a catch after it.

Before
BufferedReader bufferedReader =
    new BufferedReader(new FileReader("poem.txt"));
String line = bufferedReader.readLine();
After
try {
    BufferedReader bufferedReader =
        new BufferedReader(new FileReader("poem.txt"));
    String line = bufferedReader.readLine();
} catch (IOException e) {
    System.out.println(e.getMessage());
}
Compile

Using a token without parsing it

java: incompatible types: String cannot be converted to int

split always gives back Strings. "2026" is text until you turn it into a number.

FixParse the token: Integer.parseInt for whole numbers, Double.parseDouble for decimals.

Before
String[] parts = line.split("\\|");
int year = parts[1];
After
String[] parts = line.split("\\|");
int year = Integer.parseInt(parts[1]);
Compile

ArrayList without its import

See it
java: cannot find symbol
  symbol:   class ArrayList
  location: class Main

ArrayList lives in java.util, and Java only knows it once you import it. HashMap and List are the same.

FixAdd the import at the top, or click the red name and press Alt+Enter (Option+Enter on a Mac).

Before
package com.pluralsight;

public class Main {
After
package com.pluralsight;

import java.util.ArrayList;

public class Main {
Compile

A list of the wrong type

See it
java: incompatible types: ArrayList<String> cannot be converted to ArrayList<Integer>

The type in the angle brackets is part of the list's type. A list of names is not a list of numbers.

FixDeclare the type the list really holds. Write Integer, not int, inside the brackets.

Before
ArrayList<String> names = new ArrayList<>();
ArrayList<Integer> numbers = names;
After
ArrayList<String> names = new ArrayList<>();
ArrayList<Integer> numbers = new ArrayList<>();
Runtime

A space in a csv token

Exception in thread "main" java.lang.NumberFormatException: For input string: " 2026"
	at java.base/java.lang.NumberFormatException.forInputString(NumberFormatException.java:67)
	...
	at com.pluralsight.Main.main(Main.java:18)

The line was SUV, 2026, Black. Splitting on the comma keeps the space, and parseInt accepts digits only.

FixTrim each token before you parse it.

Before
int year = Integer.parseInt(parts[1]);
After
int year = Integer.parseInt(parts[1].trim());
Runtime

A line with fewer fields

Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 1 out of bounds for length 1
	at com.pluralsight.Main.main(Main.java:17)

Often the empty last line of the csv: splitting "" gives one empty token, so there is no parts[1].

FixSkip blank lines, or check parts.length before you read a field.

Before
String[] parts = line.split("\\|");
int year = Integer.parseInt(parts[1]);
After
if (line.isBlank()) {
    continue;
}
String[] parts = line.split("\\|");
int year = Integer.parseInt(parts[1]);
Runtime

An index past the end of a list

See it
Exception in thread "main" java.lang.IndexOutOfBoundsException: Index 3 out of bounds for length 3
	at java.base/jdk.internal.util.Preconditions.outOfBounds(Preconditions.java:64)
	...
	at com.pluralsight.Main.main(Main.java:21)

Three kids means indexes 0 to 2. remove(3) fails the same way, and after a remove the list is one shorter.

FixLoop while i < kids.size(), or use a for-each loop.

Before
for (int i = 0; i <= kids.size(); i++) {
    System.out.println(kids.get(i));
}
After
for (int i = 0; i < kids.size(); i++) {
    System.out.println(kids.get(i));
}
Runtime

Using what get returned when the key is missing

See it
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.toUpperCase()" because "capital" is null
	at com.pluralsight.Main.main(Main.java:30)

get("OK") does not throw when the key is missing: it returns null. The crash comes on the next line, when you use it.

FixCheck for null before you use the value.

Before
String capital = statesAndCapitals.get("OK");
System.out.println(capital.toUpperCase());
After
String capital = statesAndCapitals.get("OK");
if (capital != null) {
    System.out.println(capital.toUpperCase());
} else {
    System.out.println("OK is not in the map");
}
Runtime

A pattern that does not match the text

See it
Exception in thread "main" java.time.format.DateTimeParseException: Text '10/17/2026' could not be parsed at index 2
	at java.base/java.time.format.DateTimeFormatter.parseResolved0(DateTimeFormatter.java:2052)
	...
	at com.pluralsight.Main.main(Main.java:36)

The pattern says a dash comes after the month; the text has a slash at index 2. With no formatter at all, it fails at index 0.

FixWrite the pattern exactly as the text is laid out, separators included.

Before
DateTimeFormatter dateTimeFormatter =
    DateTimeFormatter.ofPattern("MM-dd-yyyy");
LocalDate newDate =
    LocalDate.parse("10/17/2026", dateTimeFormatter);
After
DateTimeFormatter dateTimeFormatter =
    DateTimeFormatter.ofPattern("MM/dd/yyyy");
LocalDate newDate =
    LocalDate.parse("10/17/2026", dateTimeFormatter);
Runtime

Dividing by zero

See it
Exception in thread "main" java.lang.ArithmeticException: / by zero
	at com.pluralsight.Main.main(Main.java:26)

Whole-number division by 0 has no answer. Inside a try, ex.getMessage() prints just / by zero.

FixCatch it, or check the divisor before you divide.

Before
int result = firstNumber / secondNumber;
After
if (secondNumber != 0) {
    int result = firstNumber / secondNumber;
}
Runtime

A letter where nextInt wants a number

See it
Exception in thread "main" java.util.InputMismatchException
	at java.base/java.util.Scanner.throwFor(Scanner.java:939)
	...
	at com.pluralsight.Main.main(Main.java:24)

nextInt() found abc. This one has no message, so ex.getMessage() prints null.

FixWrap the read in try and tell the user what you expected.

Before
int firstNumber = scanner.nextInt();
After
try {
    int firstNumber = scanner.nextInt();
} catch (Exception ex) {
    System.out.println("Please enter a number.");
}
Runtime

The prompt that skips itself

No error. Console:

Enter your choice: 1
Enter a name: Added:
Enter your choice:

nextInt() reads 1 and leaves the Enter behind. The next nextLine() takes that Enter and returns an empty String. Common in menu programs.

FixCall scanner.nextLine() once right after nextInt().

Before
int choice = scanner.nextInt();
System.out.print("Enter a name: ");
String name = scanner.nextLine();
After
int choice = scanner.nextInt();
scanner.nextLine();
System.out.print("Enter a name: ");
String name = scanner.nextLine();
Runtime

The red wall of e.printStackTrace()

See it
java.lang.NumberFormatException: For input string: "abc"
	at java.base/java.lang.NumberFormatException.forInputString(NumberFormatException.java:67)
	at java.base/java.lang.Integer.parseInt(Integer.java:668)
	at java.base/java.lang.Integer.parseInt(Integer.java:786)
	at com.pluralsight.Main.main(Main.java:14)

It looks scary but reads top down: line 1 is the exception and its message; the first com.pluralsight line is your line. The java.base lines are inside Java.

FixRead the first line, then click the blue Main.java:14 link to jump to your code.

Look at
java.base/... lines
Read
line 1 and Main.java:14
Files

The file is not where Java looks

See it
java.io.FileNotFoundException: poem.txt (No such file or directory)
	at java.base/java.io.FileInputStream.open0(Native Method)
	...
	at com.pluralsight.Main.main(Main.java:10)

A bare name like poem.txt is looked up in the working directory, which is the project root, not src. On Windows it reads (The system cannot find the file specified).

FixPut the file at the project root, next to pom.xml, and check the spelling and the extension.

Before
my-project/
  src/main/java/com/pluralsight/
    poem.txt
  pom.xml
After
my-project/
  src/main/java/com/pluralsight/
  poem.txt
  pom.xml
Files

The file is empty after writing

See it

No error. potato.txt:

(empty)

A writer holds text in memory and only puts it on disk for sure when it is closed. No close(), no text.

FixCall close() after the last write, still inside try.

Before
fileWriter.write("Hello Everyone\n");
fileWriter.write("Welcome to the Java Bootcamp!");
After
fileWriter.write("Hello Everyone\n");
fileWriter.write("Welcome to the Java Bootcamp!");
fileWriter.close();
Files

The old lines are gone

See it

No error. tomato.txt after the second run:

Counting 1
...
Counting 10

new FileWriter("tomato.txt") starts the file over on every run. Only the last run's lines are left.

FixPass true as the second argument to add to the end instead.

Before
new FileWriter("tomato.txt")
After
new FileWriter("tomato.txt", true)

Compile messages appear in the Build window, runtime ones in the Run window. Line numbers will differ in your code.
